# Measuring HEIF Display Latency with ffmpeg PPM Output

Back to the [measurement list](../measurements.md).

## 1. Subject and Conditions

2026-10-24 (UTC). After changing HEIC/HEIF and AVIF to be decoded as PPM on stdout and keeping heif-dec only for alpha and fallback, we measured the same display and thumbnail workload as [the earlier record](./2026-10-24-heif-display.md). Each run's values are in the [aggregate JSON](./2026-10-24-heif-ppm.json).

- Build: `1773c4a` of `main` with the working-tree change, release profile. The temporary ignored engine test used for the measurement was not committed.
- Environment: Debian GNU/Linux 13 (trixie) arm64 on Linux 6.12.76-linuxkit, 10 cores, 8 GiB. Rust 1.96.0. The OS file cache was not controlled.
- Tools: ffmpeg `n9.0.2-17-g2a571b6068` (BtbN static), libheif 1.23.6. heif-dec was not used for these fixtures because none has alpha.
- Fixture: one synthetic 4032×3024 image (ffmpeg's `mandelbrot`, JPEG `-q:v 2`), the same image as tiled and untiled HEIC (x265 quality 90), and as AVIF (quality 90). Hashes are in the JSON.
- Display request: a 1440×900 screen at pixel density 2, `variant=display`, width 2880, height 1800, `resize=fit`, WebP quality 90. The long edge rounds up to 4096, so resizing is a no-op for this fixture.
- Thumbnail request: width 512, height 512, `resize=fit`, WebP quality 80.
- Settings: `ThumbnailOptions::default()`.
- Procedure: each of 5 runs uses a fresh copy, so the cache misses. The display image is generated, then the same file is requested again to measure a cache hit. Another 5 fresh copies per format are used for the thumbnail. Engine-level values are `ThumbnailGenerator::generate`; the breakdown extracts PPM again and then decodes, resizes, and encodes outside the generator.

## 2. Results

### 2.1 Display Image Generation

Milliseconds. Median (minimum–maximum) of 5 cache misses. `read` is the ffmpeg PPM extraction; `decode` is decoding the PPM; resizing was a no-op.

| Source | Total | read | decode | WebP | Bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| HEIC, tiled | 408.5 (359.6–653.0) | 132.2 | 16.2 | 212.9 | 596,946 |
| HEIC, untiled | 452.5 (419.6–495.8) | 201.0 | 22.9 | 217.5 | 596,968 |
| AVIF | 476.2 (459.3–515.6) | 162.6 | 16.5 | 207.1 | 591,570 |
| JPEG | 251.7 (238.8–314.9) | 0.0 | 31.0 | 223.2 | 583,396 |

Against the [earlier record](./2026-10-24-heif-display.md), the display median fell from 935.4 to 408.5 ms for tiled HEIC (2.29×) and from 1064.4 to 452.5 ms for untiled HEIC (2.35×). AVIF was not measured before this change, so only its new value is recorded. JPEG is unchanged within run-to-run variation (251.7 ms against 258.7 ms).

The first tiled run took 653.0 ms. The other four were 359.6 to 452.3 ms. The median is below the 500 ms acceptance level; the maximum is not.

### 2.2 Thumbnail Generation and Cache Hits

Milliseconds. Median (minimum–maximum) of 5 cache misses and of 5 cache hits for the same display request.

| Source | Thumbnail 512 | Cache hit |
| --- | ---: | ---: |
| HEIC, tiled | 209.3 (199.4–254.5) | 0.55 |
| HEIC, untiled | 264.6 (259.1–292.8) | 0.57 |
| AVIF | 274.3 (271.1–320.1) | 0.36 |
| JPEG | 101.5 (100.9–102.9) | 0.38 |

The thumbnail median fell from 765.4 to 209.3 ms for tiled HEIC (3.66×) and from 908.3 to 264.6 ms for untiled HEIC (3.43×). JPEG is unchanged (101.5 ms against 102.1 ms). Cache hits are under 1 millisecond.

## 3. Conclusion

All acceptance levels were met on the medians:

| Condition | Target | Tiled HEIC | Untiled HEIC |
| --- | ---: | ---: | ---: |
| Display first generation | 500 ms or less | 408.5 ms | 452.5 ms |
| Thumbnail 512 | 300 ms or less | 209.3 ms | 264.6 ms |
| Speedup against the current path | 2× or more | 2.29× | 2.35× |
| JPEG regression | 10% or less | none | none |

The PPM decode is only 16 to 23 ms, so the PNG roundtrip is gone. WebP encoding is now the largest single part of display generation (about 210 ms), followed by the HEIC decode (about 130 to 200 ms). A thumbnail still decodes the whole image, so its cost is roughly the decode plus a small resize and encode.

## 4. Limits

- The source is one synthetic image; its content is not representative of phone photos. The absolute values should not be extrapolated to real libraries.
- The alpha path (heif-dec) was not measured at 12 megapixels. The alpha fixtures are 512×512 and 1024×1024 and are used only for correctness tests.
- The measurement is `ThumbnailGenerator::generate` without HTTP, authentication, a real network, browser decoding, or painting. All requests were sequential; concurrency, the shared limit of 2, and flipping were not measured.
- The OS file cache was not controlled. The first tiled run was slower than the rest, and the maximum is reported above.
- AVIF had no baseline measurement before this change, so the record shows only its new value.
- JXL and JP2 keep the PNG path and were not measured.
- PPM peak memory was not measured. It is expected to be about 36 MB for the PPM bytes plus the decoded image for each concurrent job.
